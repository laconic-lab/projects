### 2. Build the final Agent authority matrix

This is the central deliverable.

For every execution surface, we will document:

- How it becomes available to the Agent.
- Whether the model can invoke it.
- Whether it has an execution-time permission check.
- Whether it can act as an administrator.
- Whether it can access the host, filesystem, network or external services.
- Whether it can continue executing without user interaction.
- Whether its authority is restricted by token scope and user identity.

The result will distinguish:



Source verified

&#x20;Confirmed by current source.





Inconclusive

&#x20;Requires runtime or additional source verification.





Defect

&#x20;Confirmed policy or authorization gap.





Design decision

&#x20;Required architecture, not yet implemented.



### 3. Produce the prioritized security defect register

Each defect gets:

- Unique ID.
- Exact source location and branch.
- Evidence and explanation.
- Security consequence.
- Severity and priority.
- Required correction.
- Acceptance criteria for later implementation.

This will prevent us from fixing symptoms while leaving the underlying authority model unchanged.

### 4. Freeze the audit and prepare the implementation handover

The handover will contain:

1. Confirmed current-repository identity and source revision evidence.
2. Final Agent authority matrix.
3. Complete defect register.
4. Security architecture decisions.
5. Implementation order and dependencies.
6. Verification and regression-test requirements.
7. Explicit list of things that must remain untouched.

Only after that do we move to implementation.
