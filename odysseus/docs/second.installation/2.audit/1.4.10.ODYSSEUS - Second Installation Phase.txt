Two details matter:

1. The missing `kernel.unprivileged_userns_clone` and AppArmor sysctl entries are not automatically faults. Those controls are kernel-configuration dependent; their absence does not establish that user namespaces are unavailable.

Not yet established: the actual UID/GID mapping inside a rootless user namespace. That is essential. We must not assume container root or container UID 1000 maps to a suitably unprivileged host identity.

## A4 — Verify real UID/GID mappings and network definition

STEAM DECK — Konsole / existing SSH session

This next check opens a temporary rootless user namespace for reading its mappings. It does not create a container or alter Podman configuration.

```
echo "=== ROOTLESS UID MAPPING ==="
podman unshare cat /proc/self/uid_map

echo
echo "=== ROOTLESS GID MAPPING ==="
podman unshare cat /proc/self/gid_map

echo
echo "=== PODMAN ID MAPPING DETAILS ==="
podman info --debug 2>&1 | sed -n '/idMappings:/,/networkBackend:/p'

echo
echo "=== EXISTING PODMAN NETWORK ==="
podman network inspect podman
```
